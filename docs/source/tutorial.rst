Tutorial
========

This tutorial starts with a minimal bulk Si calculation and then introduces
the alternative workflows implemented by NEP-kappa. Run the commands from the
repository root so that the relative paths in the example YAML files resolve
correctly.

Before starting
---------------

Install NEP-kappa and verify that both command-line programs are available:

.. code-block:: bash

   python -m pip install -e .
   nepkappa --version
   python -c "import phono3py; print(phono3py.__version__)"

The provided examples use small supercells to demonstrate the workflow. They
are not convergence settings for production calculations. Converge the
supercell dimensions, q-point mesh, force-constant method, and other physical
parameters for your own system.

Step 1: Choose the input structure
----------------------------------

The first example uses the repository-provided bulk Si structure:

.. code-block:: text

   examples/POSCAR_bulk

For a different material, set ``structure.poscar`` to its POSCAR path. Paths in
the YAML file are interpreted relative to the directory in which the command is
run.

Step 2: Create a YAML input
---------------------------

Create ``input.yaml`` with the following content, or start directly from
``examples/1-bulk-nep-rta.yaml``:

.. code-block:: yaml

   structure:
     poscar: examples/POSCAR_bulk
     dimensionality: 3

   calculator:
     name: nep
     nep_model: potentials/Si_Bulk_Fan.txt

   relaxation:
     enabled: true

   force-constant:
     dim-fc2: [3, 3, 3]
     dim-fc3: [3, 3, 3]
     use_hiphive: false
     compact-fc: true

   kappa:
     mesh: [21, 21, 21]
     temps: [100, 1000, 50]
     method: rta
     isotope: false
     bfmp: 1.0e6
     wigner: false

   plot:
     layout: both
     path: seekpath
     tau: total
     kappa: all
     temperature: 300
     dpi: 300

   output:
     progress: true
     result_dir: results/1-bulk-nep-rta

The main settings in this example are:

- ``dim-fc2`` and ``dim-fc3`` define the FC2 and FC3 supercells separately.
- ``use_hiphive: false`` selects finite displacement; ``true`` selects a
  HiPhive fit to forces from rattled structures.
- ``compact-fc: true`` writes phono3py v4 compact FC2/FC3 arrays. Set it to
  ``false`` when full supercell force-constant arrays are needed.
- ``method`` accepts ``rta`` or ``lbte``. RTA is passed to phono3py using
  ``--br --nu``.
- ``temps`` must contain either one temperature, for example ``[300]``, or
  exactly three values ``[tmin, tmax, tstep]``.
- ``bfmp`` is the boundary mean free path in micrometers.
- all generated files and the run log are written below ``result_dir``.

Step 3: Validate and run
------------------------

Inspect the parsed configuration before launching an expensive calculation:

.. code-block:: bash

   nepkappa info input.yaml

Then run structure relaxation, force-constant generation, and thermal
conductivity calculation in sequence:

.. code-block:: bash

   nepkappa run input.yaml

The ``run`` command does not create plots. Plot the completed calculation with
a separate command:

.. code-block:: bash

   nepkappa plot input.yaml

Alternatively, execute each calculation stage separately:

.. code-block:: bash

   nepkappa relax input.yaml
   nepkappa fc2fc3 input.yaml
   nepkappa kappa input.yaml
   nepkappa plot input.yaml

Use ``nepkappa fc2`` instead of ``fc2fc3`` when only harmonic FC2 data is
needed. When ``relaxation.enabled`` is ``true``, separately executed ``fc2`` and
``fc2fc3`` commands expect ``POSCAR_relaxed`` in ``output.result_dir``. Run
``nepkappa relax`` first, or use ``nepkappa run``. When relaxation is disabled,
the force-constant stage reads ``structure.poscar`` directly.

The ``kappa`` stage requires ``phono3py_disp.yaml``, ``fc2.hdf5``, and
``fc3.hdf5`` in the result directory. This makes it possible to rerun only the
thermal-transport stage after changing the mesh, temperatures, scattering
options, or transport method.

Step 4: Check outputs and logs
------------------------------

The complete calculation writes the following files to
``results/1-bulk-nep-rta``:

- ``run.log``: configuration, program output, errors, and timing information
- ``POSCAR_relaxed``: relaxed structure, or a copy of the input structure when
  relaxation is disabled and the ``relax`` stage is run
- ``phono3py_disp.yaml``: structure and displacement metadata used by phono3py
- ``fc2.hdf5`` and ``fc3.hdf5``: second- and third-order force constants
- ``kappa-m*.hdf5``: thermal-transport results written by phono3py
- ``plots/``: figures generated by ``nepkappa plot``

With ``plot.layout: both``, ``plots/`` contains separate dispersion, DOS,
volume heat capacity, group velocity, relaxation time, and thermal conductivity
figures, plus ``combined.png`` with all six panels.

``nepkappa run`` starts a new ``run.log``. Separately executed ``relax``,
``fc2``, ``fc2fc3``, ``kappa``, and ``plot`` commands append their output to
the existing log, so the complete calculation history remains in one file.

For details on datasets in ``kappa-m*.hdf5``, see the
`phono3py HDF5 documentation <https://phonopy.github.io/phono3py/hdf5_howto.html>`_.

Using HiPhive
-------------

Set ``use_hiphive: true`` and provide the training and cutoff settings:

.. code-block:: yaml

   force-constant:
     dim-fc2: [3, 3, 3]
     dim-fc3: [3, 3, 3]
     use_hiphive: true
     n_structures: 100
     rattle_std: 0.03
     min_dist: 2.0
     cutoffs: [5.0, 4.0]

NEP-kappa generates rattled structures, calculates their forces with the
selected calculator, fits a HiPhive force-constant potential, enforces the
rotational sum rules, and exports ``fc2.hdf5`` and, in ``fc2fc3`` mode,
``fc3.hdf5``. The fitted model is saved as ``hiphive_model.fcp``. See
``examples/2-bulk-nep-hiphive-rta.yaml`` for a complete input.

Using VASP
----------

Select VASP in the calculator section and configure the executable and POTCAR
source for your machine:

.. code-block:: yaml

   calculator:
     name: vasp
     vasp_command: mpirun -np 24 /path/to/vasp_std
     vasp_path: /path/to/vasp_std
     potcar_path: /path/to/potpaw_PBE.64

``vasp_command`` is used to launch VASP. ``potcar_path`` may point to a complete
POTCAR file or to a potential-library directory; in the latter case NEP-kappa
assembles POTCAR entries in POSCAR element order. The relaxation and
force-constant sections can provide stage-specific INCAR settings and working
directories. Edit all machine-specific paths in
``examples/5-bulk-vasp-rta.yaml`` before running it.

VASP calculations create ``vasp-relax/`` and/or ``vasp-runs/`` below the result
directory. Inspect these directories and ``run.log`` when a VASP subprocess
fails.

Film and nanowire calculations
------------------------------

For a film, specify the physical thickness and the non-periodic cell axis:

.. code-block:: yaml

   structure:
     poscar: examples/POSCAR_film
     dimensionality: 2
     effective_thickness: 10.0
     vacuum_axis: z

For a nanowire, specify its effective cross-sectional area and periodic axis:

.. code-block:: yaml

   structure:
     poscar: path/to/POSCAR_wire
     dimensionality: 1
     effective_area: 100.0
     periodic_axis: z

``effective_thickness`` is in angstrom and ``effective_area`` is in
angstrom squared. They are required for the corresponding dimensionality and
are used to remove the artificial vacuum contribution during plot
post-processing. The raw phono3py HDF5 values are not rewritten. For films,
also use supercell dimensions and q-point meshes consistent with the
non-periodic direction, as demonstrated by ``examples/7-film-nep-rta.yaml``.

Compare DFT and NEP results
---------------------------

After both calculations are complete, edit ``examples/compare.yaml`` so that
``reference.dft_dir`` and ``candidate.nep_dir`` point to the two result
directories. Each directory must contain ``phono3py_disp.yaml``, ``fc2.hdf5``,
and a matching ``kappa-m*.hdf5`` file. Then run:

.. code-block:: bash

   nepkappa compare examples/compare.yaml

The comparison command overlays the dispersion, DOS, volume heat capacity,
group velocity, relaxation time, and thermal conductivity results. Figures are
written below ``compare.compare_dir/plots`` and command output is saved as
``compare.log`` in ``compare.compare_dir``.

Distributed LBTE with Slurm
---------------------------

For a large LBTE calculation on a Slurm cluster, add a ``parallel`` mapping:

.. code-block:: yaml

   kappa:
     mesh: [21, 21, 21]
     temps: [300]
     method: lbte
     parallel:
       backend: slurm
       jobs: 32
       submit: false

Run ``nepkappa fc2fc3`` first, then generate the Slurm workflow:

.. code-block:: bash

   nepkappa kappa input.yaml

With ``submit: false``, NEP-kappa discovers the irreducible grid points and
writes ``prepare.sh``, ``array.sh``, ``collect.sh``, grid-point lists, and a
submission manifest below ``output.result_dir/lbte-slurm`` without calling
``sbatch``. Inspect the scripts, add cluster-specific options such as
``partition``, ``time``, ``memory``, ``max-concurrent``, or ``preamble``, and
then set ``submit: true`` to submit the three stages with ``afterok``
dependencies.

All compute nodes must see the same result directory. Slurm resource settings
are left to the cluster defaults unless explicitly provided. A complete input
is available in ``examples/9-bulk-nep-lbte-slurm.yaml``.
